# 02｜P1：上游 502/503、重试与 failover 整改

- **类型：**开发设计 + 实施待办
- **优先级：**P1；依赖 [01 端到端可观测性](01-observability-design.md) 的请求关联和阶段时间
- **状态：**待实施；本文不授权生产配置变更

## 1. 背景

只读排查见上游 502/503、same-account retry、账号切换，以及完整请求长尾。代码仓库已有 `backend/internal/handler/failover_loop.go`、`sameAccountRetryAllowed`、`sameAccountRetryDelayFor` 等机制，不能另造重试器；必须先确认不同协议 handler 共用路径、错误分类和流式写出边界。核心安全约束是：不能将已部分交付给客户端的流伪装成可安全重试的完整请求。

## 2. 目标/非目标

目标：可解释每次上游尝试；明确何种错误可重试、何时可切账号、客户端已收到数据后如何终止；配置有界、可测试、可回滚。

非目标：本 change 不提高默认重试次数、不改变账号调度策略、不修改生产池配置、不保证上游服务可用。

## 3. 设计约束

1. 将错误分为：连接建立前错误、收到上游响应头前错误、上游非 2xx、响应体读取错误、首个下游字节前错误、首个下游字节后错误、客户端取消、下游写错误、内部错误。
2. “可重试”必须由现有错误类型/协议契约决定，不以错误字符串匹配作为唯一判据。
3. 实施前盘点各 handler 是否可能在已写 header/body 后调用 failover；共享响应写状态须以测试证明，不能根据 handler 名称猜测。
4. **一旦响应头或任何流体字节已提交给客户端，默认禁止透明地对另一个上游重放同一请求。**若协议允许明确的错误事件继续流，应定义协议行为，但仍不能把已经发生的部分输出重放成无痕成功。例外需逐协议 ADR/明确负责人批准。
5. 尊重 context cancellation/deadline；客户取消后停止新尝试，并确保上游 body、连接和 goroutine 释放。
6. 每个请求同时受已有次数限制和总时间预算约束；重试退避不得超过剩余 deadline。避免 retry storm；具体上限以现有配置与测量评审为准。
7. 上游响应正文仅保留有界、脱敏的错误分类；不可记录凭据或 prompt。

## 4. 实施步骤

- [ ] A. 通过 rg/调用链检查所有协议使用的 `FailoverService`/错误分类/stream writer，画出 header/body 提交状态与调用关系。
- [ ] B. 依据 [01](01-observability-design.md) 记录 `attempt_index`、错误类别、上游状态、阶段耗时、重试决策及 remaining deadline。
- [ ] C. 写重试决策表：错误类型 × 响应提交状态 × 请求可重放性 × 可否 retry/switch × 客户端结果。
- [ ] D. 在共享 failover/协议边界实施保护；若各协议语义不同，在协议 adapter 层分别实现，禁止跨协议粗暴统一。
- [ ] E. 处理并发取消、body 关闭、退避 timer 与上游连接资源的清理。
- [ ] F. 在不改变既有有效默认行为前提下评估配置；需改默认值时独立提交、给出旧值、新值、兼容性依据和回滚方式。
- [ ] G. 由上游服务 owner 提供上游 502/503 分类与状态语义；不把暂时性与永久性错误混作一类。

## 5. 必测场景

- 连接建立失败且未向客户端提交响应：按决策表可重试/切换。
- 上游 503 header 已收到但客户端响应尚未提交：验证允许行为及 body 清理。
- 已提交 200 header、已输出一个或多个 chunk 后，上游断流：不得无痕切另一账号重放。
- 客户端取消发生在退避期/上游读取中：不得启动额外尝试。
- 总 deadline 耗尽、重试上限到达、所有账号失败、账号被限流等现有规则回归。
- 多协议错误 envelope 与计费/用量记录只产生一次且语义一致。

## 6. 验收

- 决策表所有行都有实现或明确“不适用”说明。
- 自动测试证明输出提交后不会透明重放；验证请求计数、计费记录、上游 body 关闭与 goroutine 收敛。
- 现有 `failover_loop`、Gateway 流式与各受影响协议回归通过；后端 unit、lint 通过。
- 使用 P0 遥测比较变更前后：上游错误率、重试成功率、TTFT、请求长尾、客户断连和每请求上游尝试数；流量按阶段扩大并可撤回。
- 不以“总成功率提高”掩盖重复扣费、首 token 变慢或流式错误。

## 7. 发布门

测试环境 → 内部/合成流量 → 有限流量 → 观察一个覆盖业务峰谷的窗口 → 继续扩量。每阶段有负责人、停止条件、回滚提交/配置和数据对比。未经授权不得改生产账号池、重试参数或部署。
